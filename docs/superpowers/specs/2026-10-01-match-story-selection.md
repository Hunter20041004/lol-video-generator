# 賽後影片：依比賽選題，不套固定故事

日期：2026-10-01（Asia/Taipei）
狀態：使用者以「對」確認通用內容原則；本文件為編輯規格，尚非自動選題功能或實作計畫。

## 已確認的產品行為

每場影片先找有來源的比賽看點，再決定開場、主角、證據及段落。隊色、美術語言與可重用元件一致，故事不一致。約40秒與音樂不全程鋪滿的要求保留。六幕只是可用骨架，不強迫每場都走「輔助對位→資源→地圖→MVP」或「前東家→淘汰→團戰」。

觀眾看完應知道這場值得看的具體事情，而不只是知道誰的數字比較大。數據用來支持對場面或表現的理解，不能從統計反差直接捏造勝因。

## 通用編輯流程

賽事身份核對 → 查找看點候選 → 核對證據 → 選一條主線 → 撰寫40秒內容 → 場面／文字／數據分配 → 成片驗收。

像編輯先選新聞題目，再排版：不能先把六個版面填滿，才回頭替數字找故事。本流程目前由編輯查核執行；寫入規格不代表程式已能抓影片或理解交戰。

### 候選題材（不是每場必填的欄位）

- 關鍵團戰、操作、失誤或局內逆轉。
- 特殊選角、位置交換、陣容與戰術應對。
- 有具體交戰證據的選手表現或對位。
- 淘汰、晉級、紀錄或系列比分變化。
- 有可信來源的人物關係或交手背景，包括但不限於前東家。

不因某項背景容易寫，就讓它自動優先於場上表現。不強迫每場都有逆轉、恩怨或一位「勝利功臣」。某一項數據特別高不等於最值得看的場面。

### 選題門檻

候選需要說得清楚：發生什麼、涉及誰、為什麼值得看，以及證據在哪。優先選能在約40秒內展示並解釋的具體事情，不用自造的加權分數冒稱吸引力已量化。

只留一條主要故事。必要的背景與次要數據服務這條故事；刪去不影響理解的資料，不把每個候選都塞進成片。主角可以是一波團戰、一個選角、一位選手或系列轉折，不限人物。

### 證據與表述

- 遊戲畫面已回看：記局號、遊戲時間與原影片時間碼、前後結果；遊戲時間不等於播放器時間。不單靠剪輯標題證明勝因。
- 只有報導：可以有來源地敘述報導內容；操作細節、精確秒數、技能順序、地圖路線不能自行補齊。明確區分報導判斷與編輯推論。
- 人物背景：用官方紀錄或可靠報導；心理與話語用採訪支持。交易事實不等於被拋棄、仇恨或報復動機。
- 統計：標系列／單局、計算範圍；高KDA不等於整體更好，終局資源不等於取得順序或勝因。未知值不當零。
- 官方獎項與數據候選分開。不能把選手照片、隊徽或生成圖的外觀當身份與地形驗證。

## 不足資料時的備援

推薦：有可定位場面時，以場面為主、用數據解釋。成本是需要回看与查核，但能避免與實際比賽脫節。

備援：影片不能回看、來源不足或沒有可靠主線時，做精簡賽況摘要，清楚交代賽果與可查證的亮點。不編戲劇性、不重用別場的結論、不聲稱不存在的逆轉。這樣特色可能較弱，但保留可信度；不以硬湊40秒為理由加無關資訊。

## 視覺與發布邊界

峽谷圖鑑、大片雙隊色、原素材分層、可編輯文字保留。畫面焦點與各段時間依題材調整；局部內容調整不是重新選美術世界。關鍵場面的拆解可以占主要篇幅，無關的資源表或選手表不必出現。

本輪不授權新資料供應商、付費影音、影片下載／再發布或配音服務。查到公開影片不等於取得再利用權利。引用方式與來源確認後才進入相應製作；既有社群發布確認不可繞過。

## 後續驗收情境

- 一般觀眾：開場能明白這場為什麼值得看，結尾有對應回答，不靠懂統計縮寫才能理解。
- LoL觀眾：內容能指到本場具體行為；人物題材也不能完全取代比賽本身。
- 編輯：換到沒有前東家背景的比賽，仍能以操作、戰術或其他可證實的主線成立；缺證據時摘要備援不會誤導。
- 成片：可讀性、約40秒節奏、分段音樂及最後靜止依真實影片驗收。是否更吸引觀眾需日後留存／互動結果，不能只靠AI自評。
