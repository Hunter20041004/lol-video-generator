# 賽後判讀「峽谷賽事轉播」視覺修訂規格

日期：2026-09-27  
狀態：使用者已於 2026-09-27 核可「職業賽事轉播 70%＋遊戲結算畫面 30%」方向

## 為什麼修訂

目前 40 秒成品的資訊節奏、六幕結構與留白已符合核可規格，但近黑、暖白、朱紅與暗房校樣材質更像時尚編輯影片，無法讓一般觀眾第一眼感受到《英雄聯盟》。本輪只修訂美術世界、畫面元件與動態質感；保留真實資料、六幕順序、1,200 frames、最後 2 秒靜止、媒體驗證與發布安全邊界。

成功結果是：即使遮住節目名稱，觀眾仍能從峽谷色彩、海克斯框線、英雄／隊徽、物件圖示與賽後結算構圖辨認這是一支 LoL 賽事內容；同時每幕仍只有一個主焦點，不退回資訊擁擠的通用電競 HUD。

## 核心方向

採用「職業賽事轉播 70%＋遊戲結算畫面 30%」：專業、可信、具有 LoL 身分，但不逐像素模仿 Riot 客戶端。

- 主色：峽谷深藍黑 `#07141C`、海克斯金 `#C89B3C`、符文青 `#0AC8B9`、月白 `#F0E6D2`、資訊灰藍 `#6B7C86`。
- 光線：低亮度青綠環境光，金色只標示勝方、比分或本幕完成狀態；禁止霓虹彩虹、紅藍對撞與滿版 glow。
- 形狀：切角金屬框、六角節點、細窄分隔線與峽谷地形輪廓；不用圓角卡片、玻璃面板、膠囊標籤或無意義電路線。
- 素材：已驗證隊徽、英雄方形頭像、選手照片、物件圖示與召喚峽谷地圖是 LoL 身分的主要來源。裝飾不能取代真實內容。
- 排版：比分與主數據使用大型壓縮字；中文判讀維持高可讀粗黑體。英文標籤只作賽事層級與欄位提示，不搶主敘事。

## 固定畫面骨架

1080×1920 直式畫布保留 72px 安全邊界。頂部為低調系列資訊列，中段是每幕唯一主舞台，底部為六枚六角節點的故事進度。每幕至少保留約四分之一乾淨深色區域；框線只包住真正需要比較或確認的內容。

共同背景由三層構成：深藍黑底、低對比召喚峽谷等高線、局部青綠環境光。金色勝方軸線貫穿六幕，但每幕只允許一個高亮金色焦點。

## 六幕視覺

### 1. RESULT_HOOK，0–5 秒

- 像官方 BO5 比分板：兩隊隊徽、隊名與巨大 `2–3`，勝方一側出現金色勝利切角。
- 背景使用低對比峽谷地形，不放人物大圖，不在第一幕解釋勝因。
- 第一秒必須先讀到隊伍與比分；`共 5 局` 為唯一補充資訊。

### 2. MATCHUP_EDGE，5–12 秒

- 改成單一路線的對位面板：左右各一位真實英雄頭像或已驗證選手證據，中間只顯示一個主差距。
- 上方使用 TOP／JUNGLE／MID／BOT／SUPPORT 位置標識；單位必須由真實 metric 決定。
- 優勢方以金色輪廓與完整彩度呈現，另一方降彩度；不疊三列小數據。

### 3. EARLY_CONTROL，12–19 秒

- 以召喚峽谷上半區輪廓為舞台，幼蟲、預示者或早期物件使用可辨認的圖示節點。
- 主數字固定在地圖旁，不模擬精確路線、時間或擊殺位置；資料沒有提供的事情不畫。
- 青綠表示可爭奪物件，金色只標出真正取得控制的一方。

### 4. MAP_CONVERSION，19–27 秒

- 地圖轉為賽後戰果板：防禦塔、經濟與地圖壓力依序在同一證據槽切換。
- 使用一條由青綠轉金的轉換軸表示「先拿資源 → 轉成勝勢」，不使用假流程線或裝飾箭頭。
- 同一時間只顯示一個主要結果，維持既有留白。

### 5. PLAYER_PROOF，27–35 秒

- 選手照改成正式賽事選手卡：隊徽、handle、角色、數據 MVP 候選標籤與一個主數據。
- 英雄頭像形成低調英雄池帶；只有真實系列資料存在時才顯示。
- KDA、參團率、每分鐘經濟仍在同一位置輪替，不回到三欄儀表板。

### 6. FINAL_READ，35–40 秒

- 像勝利結算畫面：勝方隊徽位於金色勝利框，中央保留一句完整判讀。
- 35–38 秒輪替兩個已顯示過的證據；38 秒後移除證據，只保留隊徽、比分、結論與故事進度。
- frame 1,140 至片尾完全靜止。

## 動態語言

- 元素以 8–10 frames ease-out 定位，像轉播圖層被導播切入；不使用彈跳、故障閃爍、長距離飛入或持續漂浮。
- 金色描邊只在勝方或證據成立時完成一次短促描線，完成後靜止。
- 地圖節點使用一次 4–6 frames 點亮，不做循環脈衝。
- 換幕使用 2–3 frames 深藍遮罩與切角推進，避免白閃。
- reduced-motion 移除位移與描線進度，只保留 opacity 與最終靜態畫面。

## 真實性、安全與成本

- 只使用專案 manifest 已驗證的隊徽、英雄、選手、地圖與音樂；不得生成仿真選手或捏造遊戲事件。
- 可自行生成的只有抽象海克斯金屬、環境光與地形紋理；生成資產必須保存 prompt metadata。
- 不新增 Riot 遠端執行期依賴、付費素材、付費服務、帳號權限或發布權限。
- 不改 OAuth、公開媒體 gateway、queue、社群文案或發布確認。
- 備援方案是純賽事轉播版：若某場缺英雄或地圖證據，就用已驗證隊徽、位置與數據完成畫面，不以錯誤英雄或生成內容補洞。

## 驗收

1. 六幕抽幀在遮住節目名稱後，仍能由 LoL 專屬素材與視覺語法辨認題材。
2. 每幕可指出唯一主焦點、唯一判讀與當下唯一主證據。
3. 首幕一秒內讀到兩隊與比分；沒有被背景地圖或框線干擾。
4. 英雄、隊徽、選手與角色身分均能追溯到 manifest；缺失時採明確備援，不混用錯誤素材。
5. 地圖幕不捏造座標、路線、時間點或事件，只視覺化資料真正支持的控制與轉換。
6. 桌機接觸表與 375×812 手機檢視各做兩輪，檢查層次、留白、對比、字級、安全區與無溢位。
7. 動效審查確認沒有循環裝飾、白閃、彈跳或慢速漂浮；frame 1,140 後影格相同。
8. 中英文成品皆通過媒體驗證：1080×1920、30fps、約 40 秒、H.264／AAC、音量與起音門檻合格。
9. 完整測試、Next build、Remotion QA、資安檢查與 GitHub checks 通過後才合併。
10. 本輪只產生預覽與驗證成品，不建立 Meta container、publish job 或遠端貼文。
