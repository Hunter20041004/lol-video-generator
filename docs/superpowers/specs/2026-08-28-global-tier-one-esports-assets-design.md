# 全球 LoL 一級賽事掃描與 2026 素材庫設計

日期：2026-08-28
狀態：產品負責人已核可，可直接進入施工計畫與實作

## 產品目標

讓賽事影片工作台能掃描 Riot 2026 全球一級職業賽事，並在產生 25 秒賽後判讀前，依比賽當日的隊伍與選手身份取得正確、可追溯、已驗證的本機素材。產品不得以文字降級、錯誤人物照片、AI 人像或未驗證網路圖片掩蓋素材缺口。

## 使用者結果

- 使用者只需選擇日期；同一個系列選單會列出當天所有支援的一級賽事，不增加必要操作。
- 支援的區域聯賽為 LCK、LPL、LEC、LCS、CBLOL、LCP。
- 支援的國際賽為 First Stand、MSI、Worlds。
- 已完成且比賽資料完整的系列才能進入候選清單；未開打、進行中或資料不完整的系列不算圖。
- 素材齊全時沿用已核可的真人照、正式隊徽與 25 秒影片視覺。
- 素材不齊時停止算圖，並一次列出該影片缺少的全部選手照片與隊徽；不得只回報第一個錯誤。

## 官方範圍定義

依 Riot 2026 League Handbook，一級職業體系由五個區域構成：Americas、EMEA、Korea、China、Asia-Pacific。工作台以實際聯賽拆成六個國內／區域賽事：LCS、CBLOL、LEC、LCK、LPL、LCP，另加入 First Stand、MSI、Worlds 三項全球賽。

不納入次級、青訓、升降級外圍、表演賽、第三方盃賽或僅由名稱偶然包含聯賽縮寫的賽事。賽事登錄表必須使用明確 tournament alias／prefix 規則，不得以無邊界的 substring 判斷。

## 2026 素材涵蓋規則

### 隊伍

- 收錄 2026 一級正式賽事中參賽的全部隊伍。
- 改名、換標或品牌轉移保留日期有效區間；舊比賽解析為當時版本，不覆寫歷史身份。
- 同一隊參加國際賽時重用區域聯賽素材，不建立重複圖片。

### 選手

- 收錄一級聯賽正式登錄的先發與替補選手。
- 教練、分析師、實況主、青訓選手不收錄，除非其以一級賽事選手身份正式登錄。
- 每筆身份保存穩定 player ID、公開名稱、Leaguepedia 顯示別名、隊伍、賽區、賽季與有效日期。
- 同一選手轉隊時可以重用仍然正確的照片檔，但身份關係必須新增有效期間，不得把舊比賽歸到新隊。

### 時間界線

素材完整度只能宣稱到盤點時間點。2026-08-28 之後才公布的新人、轉隊與 Worlds 名單必須由後續盤點報告發現並核准，不能預先假裝完整。

## 素材來源政策

來源優先序：

1. Riot Games、LoL Esports 或官方聯賽媒體資產。
2. 戰隊官方網站或官方媒體資產。
3. 前兩者缺少可用圖片時，使用 Leaguepedia 保存的賽季／戰隊選手照。

禁止使用一般圖片搜尋結果、社群轉貼、來源不明鏡像、AI 生成人像或其他選手照片。隊徽只用於賽事評論中的隊伍識別；照片與商標權仍屬原權利人，不宣稱 Riot、聯賽或隊伍合作。每筆素材必須把來源與限制寫入 manifest 及 `THIRD_PARTY_ASSETS.md`。

## 儲存方案

採用「版本化本機素材庫」：壓縮後的選手照片與隊徽直接隨 Git 專案保存，render 不在每幀請求遠端資源。這延續現有 `public/player-portraits/`、`public/team-crests/` 與 JSON manifest 架構，不新增雲端服務、付費儲存或 Git LFS。

正式大量匯入前必須量測檔案數、總容量與最大單檔，並在報告中說明測量指令與涵蓋來源。若容量明顯不適合一般 Git，停止匯入並回報實測，不得擅自加入外部儲存相依。

## 系統架構

```text
          ┌─────────┴─────────┐
          │                   │
  一級賽事登錄表        2026 名單盤點器
          │                   │
  精確日期賽事查詢       缺口＋候選來源報告
          │                   │
  系列合併／完整性       人工來源核准閘門
          │                   │
          │           素材匯入／壓縮／驗證
          │                   │
          └─────────┬─────────┘
                    │
          日期感知素材解析器
                    │
       完整 → Remotion preview
       缺漏 → 聚合缺口、阻擋 render
```

## 元件責任

### 一級賽事登錄表

單一資料來源保存公開代碼、顯示名稱、類型（regional／international）、所屬區域、Leaguepedia tournament 匹配規則與排序。掃描 API、候選系列標籤及測試共用同一份登錄表，避免三處硬編碼。

### 精確日期賽事查詢

Leaguepedia Cargo 查詢以 UTC 日界 `[00:00, 次日 00:00)` 及支援賽事條件過濾並分頁；不向九個賽事各自發出無限制查詢。回傳後再次用登錄表分類，拒絕次級聯賽與近似名稱，再以日期、賽事、雙方隊伍合併系列。

### 名單盤點器

從正式賽事／名單資料建立截至指定日期的預期隊伍與選手身份，和 manifest 比對後輸出：新增、改名、轉隊、失效來源、缺照片、缺隊徽。盤點器只產生報告，不自動把候選圖片升格為正式素材。

### 素材匯入器

只接受已核准的明確來源與身份資料。下載後檢查 MIME／解碼，移除不需要的 metadata，以既有視覺需求產生 WebP 選手照或透明 PNG 隊徽，記錄 SHA-256、實際寬高、來源、驗證時間及 repository path。檔名使用穩定 ID，不使用未清理的遠端檔名。

### 素材驗證器

驗證 manifest schema、唯一身份、別名衝突、有效日期重疊、檔案路徑逃逸、格式、SHA-256、尺寸、來源欄位及預期名單覆蓋率。驗證器可在本機與 CI 執行；來源網站短暫離線不得讓已保存且雜湊正確的本機素材失效。

### 日期感知解析器

接收 player／team identity、season 與 match date，回傳該日期有效的素材版本。缺少日期或同一天命中多筆有效身份時拒絕解析。舊的無日期呼叫只在唯一、無歧義時保留相容，並逐步由正式 render path 移除。

### 聚合素材閘門

render 前先解析選手照片與雙方隊徽，再一次回傳所有缺口；沒有缺口才啟動遠端英雄素材 cache 與 Remotion。這可避免使用者修完第一個素材後才看到第二個錯誤，也減少失敗算圖前的不必要網路請求。

## 自動盤點、人工核准

- 盤點可重跑並產生可檢閱 JSON／Markdown 報告。
- 新人、新隊、改名、轉隊或新國際賽名單會出現在差異報告。
- 系統可以列出依來源優先序找到的候選網址，但不得自動核准身份或授權。
- 正式匯入需要明確列入核准輸入；匯入後再由驗證器決定能否進入正式 manifest。
- 未核准缺口保持阻擋，不以降級視覺繞過。

## 前端行為

- 日期仍是唯一必要的掃描輸入。
- 系列選單以登錄表順序及比賽時間穩定排序，label 保留賽事代碼、隊伍及比分。
- 空狀態文案改為適用全球賽事，不再暗示只掃描 LCK／LPL。
- 素材錯誤以單一 alert 顯示可理解的中文摘要及完整缺口清單；內部可保留英文錯誤碼供測試與紀錄。
- 不新增賽事篩選器；若單日系列數量的實測顯示選單不可用，再另開產品決策，不在本輪預先擴張 UI。

## 錯誤與安全

- Leaguepedia 限流沿用 cooldown 行為，不把空輸出誤判成沒有賽事。
- 未知賽事分類、資料不完整與素材缺漏是不同錯誤類型，UI 不得混為同一個「沒有賽事」。
- 任一候選素材身份、有效日期、來源或檔案驗證失敗，均不得進入正式 manifest。
- 匯入工具不得覆寫不同 SHA 的既有素材；更新必須保留版本與變更證據。
- preview 驗證完成前不得建立 publish job；素材盤點及 canary 不得碰正式發布佇列。

## TDD 與驗收

實作使用垂直 Red → Green → Refactor，一次只新增一個失敗測試。聚焦階段只跑當前測試檔；每個工作項目結束跑相關測試，收尾才跑完整 coverage、Next build、audit、Remotion QA 與 Playwright。

必要測試：

- 登錄表逐一辨識 LCK、LPL、LEC、LCS、CBLOL、LCP、First Stand、MSI、Worlds，且拒絕次級／近似名稱。
- 精確日期查詢使用支援賽事過濾與分頁，真實邊界抽查六個聯賽及已完成的 First Stand、MSI。
- Worlds 在 2026-08-28 尚未完成，以正式名稱 fixture 驗證分類；賽事發生後才可新增 live contract 證據。
- 日期感知解析覆蓋改名、轉隊、別名與歷史比賽，不得取錯時期素材。
- manifest 驗證覆蓋錯人、錯隊、錯賽季、有效日期重疊、壞檔、路徑逃逸、雜湊及尺寸不符。
- 聚合閘門一次列出缺少的選手照片與兩隊隊徽，且不呼叫 render。
- 截至盤點日的完整性報告列出總隊伍、總選手、已覆蓋與缺口；數字必須由可重跑指令產生並以已知 fixture 校準。
- 六個區域各抽一個已完成系列通過真實素材解析；First Stand、MSI 各抽一個。完整影片 canary 依 render 成本選代表案例，但所有抽樣都必須通過非 mock resolver。
- 工作台桌面 1280×800 與手機 375×812 至少兩輪截圖自檢；檢查層次、留白、字體、配色、對齊、響應式、狀態與動效。
- main 完整測試、build、audit 與 QA 通過後 push；本專案沒有正式部署 target 時只驗證既有本機網址及 GitHub CI／CodeQL，不建立重複站點。

## 成本與限制

- 主要成本是一次性素材蒐集、身份核對、Git 容量，以及賽季異動時的人工核准。
- 不新增雲端服務費；若未來素材規模超出一般 Git，再以實測另立儲存方案。
- 官方頁面與 Leaguepedia 可能缺少部分替補照片。這種情況必須以缺口回報，不得宣稱完整或用不明素材填補。
- 2026 素材庫是持續更新的時間截面；驗證報告必須標示 `asOf`，不能把 8 月完整度延伸宣稱到尚未公布的 Worlds 名單。

## 明確不做

- 不支援次級聯賽或所有第三方賽事。
- 不建立自動發布或自動核准圖片流程。
- 不改變已核可的 25 秒影片敘事與視覺方向。
- 不用文字卡、英雄圖或其他選手照片取代缺少的真人照。
- 不引入 Git LFS、S3、CDN、資料庫 migration 或付費 API。

## 完成定義

1. 九個一級賽事項目可被正確分類並由日期掃描器取得已完成系列。
2. 版本化 manifest、盤點器、匯入器、驗證器與日期感知 resolver 均有測試與可重跑指令。
3. 截至 2026-08-28 的正式名單盤點報告可重現，已核准素材全部保存於 repo；任何無法取得合格來源的項目以明確缺口列出。
4. 本場 BNK FEARX vs Nongshim RedForce 若三項必要素材均已取得核准來源，能實際產出並驗證 preview；否則錯誤一次列出全部未核准素材。
5. 全套品質閘門與使用者視角驗證通過，更新 `HANDOFF.md`、`THIRD_PARTY_ASSETS.md`，合併 `main`、push 並確認遠端檢查。
